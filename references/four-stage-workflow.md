# 四阶段拆解工作流

## 目录

1. 阶段一：用户旅程
2. 阶段二：执行单元与评测流程
3. 阶段三：功能等价编排规范
4. 阶段四：产品架构推导
5. 跨阶段交接

只执行用户要求的阶段；完整拆解按 1→2→3→4 顺序，后阶段必须引用前阶段的证据编号，不能把前阶段推断升级为事实。

## 1. 阶段一：用户旅程

### 目标

从进入页面、提交任务、接收结果，到比较、选择、评价、继续、失败或离开的用户经历。先确认当前模式，模式无法确认时标为未知。

### 必查内容

- 入口：标题、URL、登录状态、导航、历史、搜索、排行榜、输入占位、附件与模型入口。
- 时间线：原始输入、附件、指定模式/模型/输出、每侧结果、到达和完成状态、后续追问或纠偏。
- 结果区：单列/双列、匿名/公开标签、文本与媒体是否真实存在、操作入口、评价选项和揭晓时机。
- 决策点：满意/不满意、继续/结束、左/右/平局/都不好、编辑、重试、中断、切换、返回历史。
- 异常：单侧/双侧失败、超时、安全、额度、频率、权限、空结果、资产或状态不一致。

### 证据表

| 阶段 | 用户目标 | 用户动作 | 页面反馈 | 用户决定 | 页面/结果变化 | 用户情绪 | 问题或阻力 | 证据等级 | 证据编号与原文 |
|---|---|---|---|---|---|---|---|---|---|

情绪只能写“可能感到……”，且必须由界面反馈支持。

### 旅程图

只保留三条泳道：用户、产品界面、系统结果。判断节点使用菱形，分支明确写条件；至少覆盖正常主流程、修改/纠偏、失败与中断。无证据节点使用虚线并标“尚未确认”。每个节点附证据编号。

### 交付顺序

查看范围 → 当前模式与入口 → 无法确认 → 截图清单 → 证据表 → HTML 旅程图 → 三类流程摘要 → 产品机会 → 三个 UX 问题。

## 2. 阶段二：执行单元与评测流程

### 目标

识别页面中实际出现的每个执行单元，拆解输入、公开判断、可见动作、输出、状态、上下游和交接。普通模型响应不自动称 Agent；UI 控件不自动称后台工具。

### 执行单元清单

| 编号 | 名称 | 类型 | 首次出现 | 触发者 | 接收者/下游 | 是否重复 | 证据等级 | 证据 |
|---|---|---|---|---|---|---|---|---|

页面无正式名称时使用功能性名称，并注明“功能命名，非产品官方名称”。

### 六类输入

1. 用户当前输入：文本、附件、模式、模型、输出类型、追问、编辑、评价、中断。
2. 会话上下文：Conversation、历史轮次、输入版本、响应槽位、模型公开状态、任务状态。
3. 用户和账号可见信息：登录、语言、权限、历史、额度、频率、偏好。
4. 上游执行单元输出：模式、规范化输入、上一轮结果、公开步骤、评价、揭晓、错误。
5. 平台公共规则与模型信息：模型列表、能力、匿名、上下文、第三方处理、安全、评价和计费提示。
6. 运行时结果：流式文本、媒体、成功/失败、超时、安全、中断、状态与历史变化。

### I/O 契约卡

每个单元固定输出：类型与核心目标、触发条件、输入信息、可观察判断、可见动作/功能性工具、输出信息、上下文读写、完成条件、异常/中断/重试、未知问题。

上下文表：

| 字段或对象 | 读取/写入 | 生产者 | 消费者 | 更新时机 | 证据等级 | 证据编号 |
|---|---|---|---|---|---|---|

### 功能性动作命名

页面无官方工具名时可使用：`<创建或加载会话>`、`<读取会话上下文>`、`<选择或分配模型>`、`<向模型提交输入>`、`<接收流式响应>`、`<保存响应结果>`、`<记录用户评价>`、`<揭晓模型身份>`、`<更新历史记录>`、`<运行 Agent 任务>`、`<处理附件或媒体>`、`<安全或权限检查>`。所有名称均注明“功能命名，非官方工具名”。

### 全局数据流

至少输出：会话上下文字段、输入—模型—响应、响应—评价—揭晓、历史写入、错误/中断、生产者—消费者。Agent Mode 任务—步骤—结果只在有证据时输出。

### 交付顺序

范围与缺口 → 模式与时间线 → 执行单元清单 → I/O 卡 → 功能性工具 → 上下文表 → 生产者/消费者 → 流程图 → 事实/推断/未知 → 五个待验证问题。

## 3. 阶段三：功能等价编排规范

### 目标

只选择一个证据充分的执行单元，描述复现用户可见行为所需的输入、状态、执行、验证和交接规则。标题必须写“功能等价”或“行为规范”，并声明不是官方 System Prompt、私有算法或隐藏指令。

### 边界表

| 属于该单元 | 不属于该单元 | 尚未确认 | 证据编号 |
|---|---|---|---|

边界必须回答：用户问题、接管时机、触发者、单/双模型、模型选择/匿名/揭晓/评价责任、上下文继承、下游交接、重新触发、停止条件和未知行为。

### 输入与输出契约

输入沿用阶段二的六类来源：

| 输入字段 | 来源 | 必填/可选 | 使用时机 | 缺失处理 | 证据等级 | 证据编号 |
|---|---|---|---|---|---|---|

| 输出字段 | 输出类型 | 消费者 | 成功条件 | 验证方式 | 证据等级 | 证据编号 |
|---|---|---|---|---|---|---|

### 工具契约

只使用页面支持的功能性工具名。每个工具说明调用时机、参数、前置检查、成功/失败、重试、幂等、中断、状态写入、双槽位防串位和匿名隔离。

### 状态机

从以下模板中只保留事实或复现行为必需的状态：`waiting_input`、`validating_input`、`selecting_mode`、`selecting_models`、`running`、`streaming`、`partial_failed`、`waiting_evaluation`、`revealing_models`、`completed`、`failed`、`interrupted`、`retrying`、`handoff`。说明每个状态允许/禁止动作、进入/退出条件和证据编号。

### 规则类型

- 【事实规则】：页面直接支持。
- 【推断规则】：复现已观察行为需要的最小推导。
- 【建议规则】：为稳定、安全、幂等和可审计而新增。
- 【未知】：无法判断。

### 编排规范固定结构

执行单元名称 → 角色 → 核心目标 → 任务边界 → 输入契约 → 会话/评测上下文协议 → 工作流程 → 模型调用规范 → 用户评价与揭晓 → 结果验证 → 修改与回退 → 异常处理 → 状态机 → 下游交接 → 完成条件 → 输出格式。

完成不能只依赖“调用成功”或界面文案；必须验证结果存在、槽位归属、输入版本、状态写入、匿名隔离、评价/揭晓一致性和历史写入。

### 最小测试集

至少覆盖：单模型成功、双模型成功、单侧失败、追问、编辑、中断、附件失败、匿名提前泄露、评价写入失败、页面状态/资产冲突、Agent 步骤失败（适用时）、重复请求。

| 测试输入 | 初始状态 | 预期判断 | 预期功能调用 | 预期状态变化 | 禁止行为 |
|---|---|---|---|---|---|

## 4. 阶段四：产品架构推导

### 目标

组合前三阶段和补充证据，解释用户、界面、会话、模式编排、模型/Agent、响应、评价/揭晓、排行榜、资产、历史、安全和治理如何协同。

### 功能域表

| 功能域 | 用户入口 | 核心对象 | 输入 | 输出 | 关键状态 | 证据等级 | 证据编号 |
|---|---|---|---|---|---|---|---|

检查账号与权限、会话与历史、搜索、输入/附件、模式、模型目录、单/双响应、流式结果、媒体预览、评价、揭晓、排行榜、编辑/重试/中断、安全、额度、频率和错误。

### 四种模式

- Battle：输入 → 匿名双槽位 → 双结果 → 评价 → 揭晓 → 评测数据。
- Side by Side：选择两模型 → 同一输入 → 双结果 → 继续对比。
- Direct：选择单模型 → 多轮对话 → 历史。
- Agent Mode：复杂任务 → 公开规划/执行状态 → 结果 → 失败或中断。

只有有证据的模式进入 As-Is；其他模式作为未知或待补证。每条模式流同时表现用户交互、页面控制、执行、数据状态和资产五种流。

### 产品分层

1. 用户与账号层。
2. 交互与工作台层。
3. 会话与模式应用层。
4. 编排与状态层。
5. 评测与排行榜层。
6. Agent 运行层（有证据时）。
7. 模型接入与路由层。
8. 资产与结果层。
9. 数据与上下文层。
10. 安全与治理层。

### 上下文模板

可按需要使用 `UserContext`、`ConversationContext`、`ModelContext`、`ResponseContext`、`EvaluationContext`、`AgentRunContext`、`AssetContext`、`WorkflowState`、`LeaderboardContext`。这些名称默认属于推导设计，除非页面或官方资料显示真实字段。

| 上下文 | 核心字段 | 生产者 | 消费者 | 更新事件 | 失效规则 | 证据等级 | 证据编号 |
|---|---|---|---|---|---|---|---|

### 架构产物

- “会话—响应—评价—揭晓—排行榜”数据流，未知连接用虚线。
- 底层能力表：先说明能力，再给可能选型与推荐方案，不猜厂商、语言或数据库。
- 数据实体表与 Mermaid ER 图；模板名不冒充真实表名。
- Battle 时序图；Agent Mode 仅在有证据时画 As-Is，否则标推断或省略。
- HTML 分层全景图：实线已确认、虚线推断、点线/特殊色建议。
- As-Is 与 To-Be 两表。
- 风险表：输入/附件不一致、响应串位、匿名泄露、空结果、单侧失败、评价/揭晓不一致、重复执行、中断失效、历史冲突、Agent 状态冲突、排行榜污染、附件隐私和权限泄漏。

### 交付顺序

执行摘要 → 证据与缺口 → 功能域 → 四模式流 → 分层架构 → 编排/模型/响应/评价关系 → 上下文 → 匿名评测/排行榜 → Agent → 模型接入 → 底层能力 → 实体/ER → 时序 → HTML 全景图 → As-Is → To-Be → 风险 → 组件追溯 → 未知问题。

## 5. 跨阶段交接

| 上游 | 下游最少交付 |
|---|---|
| 阶段 1 → 2 | 模式、时间线、用户动作、页面状态、关键证据与截图、冲突 |
| 阶段 2 → 3 | 目标执行单元、六类输入、I/O、状态、功能动作、上下文读写、未知问题 |
| 阶段 3 → 4 | 事实/推断/建议规则、状态机、完成条件、异常、交接字段、测试缺口 |
| 全阶段 → HTML | 证据目录、截图目录、图例、来源、更新时间、敏感信息复查结果 |

任何阶段发现新证据时，可以补充上游台账，但不得静默改写既有证据等级。
