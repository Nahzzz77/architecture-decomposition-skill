1. 文件结构

## 1. 文件结构

完整拆解默认生成：

```text
architecture-report/
├── 01-user-journey.html
├── 02-execution-units.html
├── 03-orchestration-spec.html
├── 04-product-architecture.html
└── assets/
    └── screenshots/
```

HTML 使用内联 CSS 和内联原生 JavaScript，不依赖外部 UI、图表或字体库。截图使用相对路径。需要 Mermaid 时，把源码作为可复制代码块保留，并用 HTML/CSS 或内联 SVG 提供无需外部库的可见图。

## 2. 页面结构

每份页面至少包含：

- 报告标题、目标页面、查看日期、范围和当前模式。
- 证据等级图例。
- 固定或吸顶目录，锚点可跳转。
- 执行摘要和关键指标卡。
- 当前阶段要求的完整表格、流程图或架构图。
- 事实、推断、建议、未知和冲突的独立视觉样式。
- 截图清单和证据目录；点击 `E01` 可跳到证据说明。
- 证据缺口、待用户补充、风险/痛点和下一步验证问题。
- 数据来源、隐私说明和生成时间。

阶段一额外包含用户情绪曲线/标签、痛点卡和机会点。阶段二包含执行单元筛选、I/O 卡和数据流。阶段三包含可复制的功能等价 Prompt、状态机、追溯表和测试集。阶段四包含分层主图、模式切换、As-Is/To-Be、ER/时序源码、风险优先级和组件追溯。

## 3. 图形与证据交互

- 已确认：实线、绿色或蓝色；推断：虚线、黄色；建议：点线、紫色；未知：灰色虚线。
- 判断节点使用菱形，分支文字写在连线上或紧邻箭头。
- 节点标签必须包含用户目标/动作、界面反馈、状态或结果，以及证据编号。
- 不把十层架构压成不可读的一张图；主图回答核心问题，细节放到分区或切换面板。
- 提供“全部 / 已确认 / 推断 / 建议 / 未知”筛选器；隐藏元素后保持布局可读。
- 证据编号使用 `<a href="#E01">E01</a>`，证据目录使用稳定的 `id="E01"`。
- 截图缩略图可点击放大；关闭弹窗支持按钮、背景点击和 Escape。

## 4. 可访问性与打印

- 设置 `<html lang="zh-CN">`、`meta charset` 和移动端 viewport。
- 正文对比度、字号和行高满足长报告阅读；不要只靠颜色区分类别。
- 所有按钮可键盘聚焦，使用原生 `button`，图片有描述性 `alt`。
- 表格置于可横向滚动容器；冻结表头时不得遮挡内容。
- 小屏改为单列，图形容器可横向滚动。
- 提供 `@media print`：隐藏交互按钮、展开全部内容、保留证据编号、避免卡片跨页断裂。

## 5. 验证流程

1. 替换全部 `{{...}}` 语义占位符。
2. 运行 `python3 scripts/validate_report.py --phase <phase> <html>`。
3. 修复所有错误；警告逐条人工确认。
4. 在浏览器打开最终文件，逐段检查导航、筛选、弹窗、表格、截图和代码块。
5. 使用桌面与窄屏两种视口截图复查。
6. 检查打印预览，避免深色背景浪费墨水或内容裁切。
7. 再次人工检查账号、邮箱、头像、私人会话标题和附件名。

阶段参数：`journey`、`execution`、`orchestration`、`architecture` 或 `auto`。

## 6. 飞书上传包

飞书可直接上传 ZIP 作为文件；HTML 在线预览能力可能因租户策略不同而变化。上传包应同时保证：下载解压后可离线打开、资源路径完整、文件名易懂。

运行：

```bash
python3 scripts/package_reports.py \
  --output 架构拆解报告_飞书上传版.zip \
  01-user-journey.html \
  02-execution-units.html \
  03-orchestration-spec.html \
  04-product-architecture.html
```

脚本会：

- 逐份运行结构与敏感模式校验。
- 为每份报告建立独立目录，避免同名资源冲突。
- 只复制 HTML 明确引用且位于报告目录内的本地资源。
- 生成 `上传说明.txt` 和 `报告索引.html`。
- 拒绝静默覆盖已有 ZIP；确需覆盖时使用 `--force`。

打包后执行 `unzip -t <zip>`，并解压到临时目录打开 `报告索引.html` 验证四份链接。
